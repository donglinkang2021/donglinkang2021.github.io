Visual tokenizers in multimodal models

An interactive field guide

Follow pixels into a language model, and separate that interface from an image codec.

What was already possible

Three meanings of an image token

Section titled “Three meanings of an image token”

In a VQ autoencoder, an image token is often a codebook index. In a ViT, it is usually a continuous feature vector. In an LLM input, an image placeholder ID marks where a visual vector will be inserted. The placeholder is not a visual vocabulary entry that encodes the image by itself.

A visual tokenizer can mean the complete input path: resize, split pixels, encode features, reduce positions, and align widths. A reconstruction tokenizer also needs a pixel decoder and a suitable objective. A model that answers questions about an image does not thereby provide that decoder.

Similar token counts can hide different computations

Section titled “Similar token counts can hide different computations”

Qwen3-VL and Qwen3.5 use learned mergers: four neighboring feature vectors are concatenated and passed through an MLP. Gemma 4 encoder variants average groups of nine encoded spatial positions. Gemma 4 12B directly embeds larger pixel blocks. These operations differ in what is mixed before positions are reduced.

Qwen3-VL adds intermediate visual features to three early LLM layers. In the inspected Qwen3.5 implementation, only the final merged visual output enters the LLM input path. Gemma 4 must be split into small-encoder, large-encoder and encoder-free variants. The table below uses specific checkpoint revisions, not family-wide guesses.

Training and inference

Section titled “Training and inference”

Why the pretraining objective matters

Section titled “Why the pretraining objective matters”

CLIP uses contrastive image–text matching. SigLIP uses a sigmoid-based pairwise objective; SigLIP-2 adds a broader training recipe. DINO-style methods use self-distillation across image views. These objectives can yield useful semantic features, but they do not explicitly require exact recovery of every pixel.

Multimodal text training can update a connector, an encoder and an LLM under different schedules. A frozen encoder still computes features, and its input gradients may still exist. An early-fusion training claim does not mean that the architecture lacks an encoder. Weight quantization for deployment does not make continuous visual features into VQ codes.

What this does not establish

Section titled “What this does not establish”

What can transfer to a reconstruction project

Section titled “What can transfer to a reconstruction project”

A useful UAR experiment would freeze one specified encoder and compare a decoder trained on features before and after the merger. Hold image data and decoder capacity fixed, and measure reconstruction, semantic utility and cost separately. This is a proposed experiment, not a result reported by the three families.

This survey is a snapshot checked on 2026-11-03. It focuses on the named families. It does not rank incomparable benchmark numbers, infer missing visual pretraining recipes, or replace the current VAR-first roadmap.

Check your understanding

Section titled “Check your understanding”
Do equal visual-token counts imply equal compression or quality?

No. Feature width, input resolution, representation type, training and downstream use can differ.
