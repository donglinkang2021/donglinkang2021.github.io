Qwen3.5: audit the visual input path

An interactive field guide

Native multimodal training does not tell you which visual modules are present. Follow the pinned implementation.

Before this article: Visual tokenizers in multimodal models · Qwen3-VL: from patches to DeepStack

What was already possible

Section titled “What was already possible”

Native multimodal training still uses a vision encoder

Section titled “Native multimodal training still uses a vision encoder”

The official model card describes early fusion of multimodal tokens during training. This describes when modalities are trained together. It does not imply an encoder-free architecture. The same card calls the model a causal language model with a vision encoder.

We inspect 2B, 9B and 397B-A17B checkpoints. The 9B example has a 27-block, width-1152 visual Transformer and width-4096 language embeddings. The smaller 2B vision tower has 24 blocks and width 1024, with output width 2048. Architecture dimensions do not identify the training dataset or initialization checkpoint.

Follow the visual encoder, not the text-model label

The vision path uses 2×16×16 RGB tubelets, a learned Conv3d embedding, interpolated absolute positions, spatial rotary positions and vision Transformer blocks. The text backbone combines different attention mechanisms, but that does not make the vision tower a linear-attention encoder. Inspect the two modules separately.

z += interpolate_absolute_positions(grid_thw)
for block in vision_blocks:

The merger connects visual width to language width

The final merger applies LayerNorm, packs spatial 2×2 groups and runs a GELU MLP. For a prepared 512×512 image, 1024×1152 encoder features become 256×4608 concatenated vectors, then 256×4096 language-width features. Concatenation preserves the four vectors as separate coordinates before the learned projection.

merged = vision_output.pooler_output
image_mask = locate_image_placeholders(input_ids)
inputs_embeds = inputs_embeds.masked_scatter(image_mask, merged)

A checked difference from Qwen3-VL

Section titled “A checked difference from Qwen3-VL”

All three inspected Qwen3.5 configurations have an empty deepstack_visual_indexes list. Configuration alone is not sufficient evidence, so we also trace the implementation. It does not return the Qwen3-VL DeepStack feature list or add it after early LLM blocks.

This is a code observation for the pinned checkpoints and implementation. It does not show that removing DeepStack caused any reported quality gain. The two families also differ in language models, data and training. A causal claim would need a matched ablation.

Work through the mechanism

Section titled “Work through the mechanism”

The merger connects visual width to language width

Section titled “The merger connects visual width to language width”

The final merger applies LayerNorm, packs spatial 2×2 groups and runs a GELU MLP. For a prepared 512×512 image, 1024×1152 encoder features become 256×4608 concatenated vectors, then 256×4096 language-width features. Concatenation preserves the four vectors as separate coordinates before the learned projection.

The visual vectors replace image-placeholder embeddings through a mask. A repeated placeholder ID therefore marks positions; the image-specific content is carried by the inserted vectors. There is no nearest-neighbor codebook lookup in this inspected path.

[1024,1152]→[256,4⋅1152]→[256,4096][1024,1152]\rightarrow[256,4\cdot1152]\rightarrow[256,4096][1024,1152]→[256,4⋅1152]→[256,4096]

Training and inference

Keep training claims separate from source observations

Section titled “Keep training claims separate from source observations”

The model card reports a unified vision–language foundation and broad multimodal results. It does not provide, in the materials audited here, a complete vision-only pretraining recipe or an unambiguous initialization checkpoint for the visual tower. Those fields remain undisclosed in this survey. Similarity to Qwen3-VL does not fill them in.

The Qwen3.5 repository entry now redirects to a newer family. This article therefore cites fixed Qwen3.5 model revisions and source commits. It does not silently use a newer README or an Omni model report as evidence for these checkpoints.

What a reconstruction experiment would still need

Section titled “What a reconstruction experiment would still need”

Early fusion does not create a pixel decoder. A reconstruction study must select pre-merger or post-merger features, define how a decoder handles their spatial layout, and train against images. Text-generation success is not a reconstruction metric.

Use the calculator to inspect sequence and width changes, including repeated terminal video frames. It counts shapes only. It cannot rank Qwen3.5 against Qwen3-VL, estimate missing training cost, or predict how much pixel detail survives the merger.
