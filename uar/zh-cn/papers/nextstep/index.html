NextStep-1：因果语言模型中的连续图像

交互教程

共享因果 Transformer 可用一个头预测离散文字，另一个头预测连续图像 patch。

前置阅读：MAR · 注意力与自回归 · 扩散与 Flow Matching

之前已经能做什么

Section titled “之前已经能做什么”

MAR 展示扩散头如何建模连续下一 token 分布；文本语言模型已有因果序列主干。NextStep-1 大规模结合这两种接口，保留严格因果顺序，并不要求图像随机顺序生成。

先认识本方法使用的工具

Section titled “先认识本方法使用的工具”

Flow matching 训练时间条件网络，预测构造的数据／噪声路径上的速度；采样通过多步积分学习场。局部平方误差目标不等于最终随机输出是直接均值回归。

Teacher forcing 在训练 next-token predictor 时提供此前真实 token；自由生成时这些 token 来自采样。因此训练时重建 teacher-forcing 预测，不等于重建完整自由采样序列。

码率—失真权衡平衡编码长度与重建误差。较短 token 序列不自动等于较低比特码率，还要考虑码本数、通道宽度与数值精度。表示载荷应与 encoder、decoder 计算分别统计。

改变了什么，为什么

Section titled “改变了什么，为什么”

主干从 Qwen2.5-14B 初始化。文字位置用类别交叉熵，图像位置用逐 patch flow-matching MLP。下一图像 token 通过以主干状态为条件的内层 flow 过程采样。共享序列可同时包含文字 ID 与投影后的连续图像向量。

32⋅32⋅16=256⋅64=1638432\cdot32\cdot16=256\cdot64=1638432⋅32⋅16=256⋅64=16384

共享序列不要求共享输出分布

Section titled “共享序列不要求共享输出分布”

NextStep-1 从 Qwen2.5-14B 初始化因果骨干。文本仍是离散词表，图像使用连续 VAE 向量；不同输入投影把二者映射到主干宽度。下一位置由文本 head 预测 ID，或由 flow head 采样图像向量。一个文本词表 softmax 不能表示连续图像输出接口。

图像 tokenizer 下采样 8 倍、16 通道。256² 时，2 × 2 space-to-depth 将 32 × 32 × 16 latent 变为 256 个 64 维向量，保留 16,384 个标量。逐通道标准化与 decoder 鲁棒性重要，因为生成向量的统计可能不同于 encoder 输出。

对照作者 Figure 2

Section titled “对照作者 Figure 2”

文本 ID 与打包后的连续图像向量进入同一条因果序列。文本词表头使用交叉熵，图像头学习 flow 目标。生成时外层推进一个位置，内层 flow 循环采样下一个图像向量。

逐步理解机制

Section titled “逐步理解机制”

微调 Flux VAE 将 256² 图像变成 32 × 32 × 16 latent。每 2 × 2 区域合入通道后，序列为 256 个 64 维 token，标量总数仍是 16384。分组演示改变分组大小并检查守恒；序列更短本身不等于信息压缩更强。

主干第 i 位置隐状态预测第 i+1 位置。目标值与图文 mask 都应一起错位。若待预测图像值已进入同一上下文位置，低训练 loss 可能反映目标泄漏，而非学习有效。

外层 AR 与内层 flow 循环

Section titled “外层 AR 与内层 flow 循环”

骨干根据此前图文 token 计算上下文 hᵢ。固定该上下文，flow head 将噪声变为下一个图像向量。完成后把向量加入序列，推进骨干，再重复。严格因果历史可使用 KV cache，但每个图像 token 的 flow head 仍需自己的采样步数。

hi=F(x<i),zt=(1−t)zi+tϵ,LFM=E∥vθ(zt,t,hi)−(ϵ−zi)∥2h_i=F(x_{<i}),\quad z_t=(1-t)z_i+t\epsilon,\quad L_{\rm FM}=\mathbb E\|v_\theta(z_t,t,h_i)-(\epsilon-z_i)\|^2hi​=F(x<i​),zt​=(1−t)zi​+tϵ,LFM​=E∥vθ​(zt​,t,hi​)−(ϵ−zi​)∥2

公式采用本站数据位于 t=0 的约定解释 flow matching，实际实现须匹配自己的求解器。文本交叉熵和图像 flow loss 作用于不同目标位置，应显式归一化与加权；把 64 维向量算成一个位置，不会自动使其损失尺度等于一个文本 ID。

移位一位就是信息边界

Section titled “移位一位就是信息边界”

用于预测图像 token i 的状态不能已经消费其干净输入。已核查损失路径将 labels 与 image indices 移位一位。应把这个操作与模态标记、图像投影和 causal mask 一起检查。损失张量形状正确，仍可能监督错误位置。

论文指定标准一维 RoPE。所查仓库存在二维坐标 helper，但相关 Python 路径中未找到其调用。存在 helper 不证明发布模型实际使用它；仓库还包含 NextStep-1.1，所以代码和 checkpoint 都须固定版本。

训练与采样的区别

Section titled “训练与采样的区别”

论文使用标准一维 RoPE。严格因果历史允许 KV cache，但图像 token 仍需外层顺序生成。图像头有 12 层、约 157M 参数。解码器噪声增强及逐通道 latent 标准化属于 tokenizer 接口，不能悄然省略。

鲁棒解码与谨慎分析伪影

Section titled “鲁棒解码与谨慎分析伪影”

论文训练 decoder 时加入 latent 噪声，强度在 [0,γ] 均匀采样，消融选择 γ=0.5。Tokenizer 微调报告 50k steps、batch 512、学习率 1e-5、1k warmup、AdamW betas (0.9,0.95)。这部分训练须与大得多的图文模型训练预算分开。

作者观察到强 guidance 可能造成逐 token 均值／方差漂移，通道标准化可缓解。这不能证明全部网格伪影都源于 guidance，也不能证明一维 RoPE 在任何设置下都无影响。诊断时记录逐通道采样统计、guidance scale、tokenizer 范围与 decoder 噪声配方。

长训练前检查打包逆变换、归一化逆变换、目标移位、缓存前后等价及两种损失 mask。论文延迟表基于计算／带宽假设，不是本地测量；应另行报告实测延迟，并计入 flow head 迭代。

这些结果不能证明什么

Section titled “这些结果不能证明什么”

当前仓库也包含 NextStep-1.1。代码中存在二维索引 helper，不证明原模型调用它。论文将强 CFG 伪影与 token 统计漂移联系起来，同时保留部分空间伪影问题，不能证明所有网格缺陷都仅由一维位置导致。其延迟表为理论估算，不是本文实测。

检查理解

Section titled “检查理解”
2 × 2 分组会丢弃 latent 标量吗？

不会。它把四个位置重排为一个更宽向量。信息损失来自 tokenizer 等其他步骤，而非这种可逆 reshape。
