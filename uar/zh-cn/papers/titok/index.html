TiTok：用短序列描述图像

交互教程

展开网格仍然每个位置对应一个 token；TiTok 改为学习少量全局 latent slots。

前置阅读：ViT · VQGAN · 评估

之前已经能做什么

Section titled “之前已经能做什么”

VQGAN 将图像压缩为较小空间网格并逐位置量化。网格提供局部结构，但长度绑定分辨率与下采样倍数。TiTok 追问：瓶颈必须保留这种一一对应的空间布局吗？

先认识本方法使用的工具

Section titled “先认识本方法使用的工具”

向量量化（VQ）用有限码本中的最近向量替换连续特征。存储索引是离散的，decoder 接收所选向量；straight-through 为硬选择提供训练导数。

自注意力根据 Q/K 相似度加权混合 token 的 value。Mask 决定哪些 token 可参与，位置编码提供几何，causal mask 提供信息边界；它们是不同设计选择。

码率—失真权衡平衡编码长度与重建误差。较短 token 序列不自动等于较低比特码率，还要考虑码本数、通道宽度与数值精度。表示载荷应与 encoder、decoder 计算分别统计。

改变了什么，为什么

Section titled “改变了什么，为什么”

编码器同时读取图像 patch 与 K 个学习 slots。自注意力让每个 slot 收集全图信息，只有 slot 输出经过向量量化。解码器将量化 slots 与带位置的 mask queries 结合，恢复稠密输出。slots 有身份，但没有固定像素邻域。

zq=Q(E([xpatch,s1:K])slots)z_q=Q(E([x_{\mathrm{patch}},s_{1:K}])_{\mathrm{slots}})zq​=Q(E([xpatch​,s1:K​])slots​)

Slots 是学习得到的瓶颈

Section titled “Slots 是学习得到的瓶颈”

把 K 个可训练 slot 向量接到图像 patch 序列后。自注意力让 slots 读取 patch 信息并相互交流。编码后丢弃 patch 输出，只保留 slot 输出。这个丢弃操作规定了瓶颈接口：解码器不能通过隐蔽 skip connection 读取被丢掉的 patch 特征。随后对保留的每个 slot 量化。

[Hx,Hs]=E([Xpatch;S]),Z=Q(Hs),∣Z∣=K[H_x,H_s]=E([X_{\rm patch};S]),\quad Z=Q(H_s),\quad |Z|=K[Hx​,Hs​]=E([Xpatch​;S]),Z=Q(Hs​),∣Z∣=K

若有 256 个图像 patch 和 32 个 slots，编码器最初处理 288 个 token，不是 32 个。只有下游表示变短。4,096 项码本的 ID 定长需要 12 bit，32 个 ID 共 384 bit，尚未计额外开销。解码器仍须构造全部输出位置。短 latent 并不让所有训练步骤都便宜。

逐步理解机制

Section titled “逐步理解机制”

跟踪一张 256² 图像：patch 特征进入编码器，32 个 latent 向量离开瓶颈，多组输出 queries 恢复空间网格。更多输出 query 不意味着编码信息更多，而是向同一紧凑表征提出不同空间问题。

演示保留信号的全局基函数系数。减少系数数量并观察丢失频率，可理解全局瓶颈，但它不复现学习到的注意力或 TiTok 质量。论文比较的是不同 K 的训练模型，并非这里的解析阈值。

32 个 slots 如何恢复完整图像

Section titled “32 个 slots 如何恢复完整图像”

解码器需要同时知道“有哪些信息”和“要放到哪里”。量化 slots 提供前者，带位置编码的 mask queries 提供输出位置。解码器混合这些序列并预测密集目标。Query 不是缺失的原像素值，而是对某个位置的信息请求。

Y^=D([Z;M+Pout])query,Lproxy=−∑ilog⁡pθ(yiteacher∣Z)\hat Y=D([Z;M+P_{\rm out}])_{\rm query},\qquad L_{\rm proxy}=-\sum_i\log p_\theta(y_i^{\rm teacher}\mid Z)Y^=D([Z;M+Pout​])query​,Lproxy​=−i∑​logpθ​(yiteacher​∣Z)

原论文主配方用已有 MaskGIT-VQGAN tokenizer 的码作为目标，再把相应编码表示送入已有像素解码器。这把学习紧凑表示与从零学习全部像素统计分开，但 proxy loss 也继承教师的表示选择及依赖。完全直接的像素解码器属于另一配置。

训练与采样的区别

Section titled “训练与采样的区别”

原论文主要方案先预测现有 MaskGIT-VQGAN 的 proxy codes，并用它的像素解码器生成图像。第二阶段冻结编码器与量化器，微调解码路径。另一个 MaskGIT 生成 TiTok codes。因此 tokenizer 重建与 code 生成具有不同目标和成本。

为什么解码器微调会改变结果

Section titled “为什么解码器微调会改变结果”

Proxy 训练后冻结 encoder 与 quantizer，微调解码端做图像重建。这样保持离散接口稳定，同时改善图像映射。若 encoder 继续漂移，码的含义也会变化，不再是同一两阶段配方。报告设置中，L-32 消融的 rFID 从微调前 5.48 变为微调后 2.21，不能把变化只归因于选了 32 个 slots。

已核查代码对 image patches 和 latent slots 使用不同的可学习位置编码。Legacy 分支还涉及 latent reshape 行为。先核对 checkpoint 的 slot 顺序和通道排列，再检查 ID 解码与编码 forward 的重建是否一致。Decoder 微调期间，确认 encoder、slot 参数和 quantizer 都不更新。

生成是额外阶段：MaskGIT 式模型预测 TiTok ID。Tokenizer 重建需要编码与解码路径，生成还需要 latent 采样过程。报告时应同时写 K、码本大小、tokenizer 变体、decoder 是否微调及生成器设置。32-token 的重建成绩和 128-token 的生成成绩不能拼成一个配置。

这些结果不能证明什么

Section titled “这些结果不能证明什么”

Transformer tokenizer 并不保证部署解码器完全没有 CNN；原方案使用 proxy 模型与像素解码器。不能将 32-token 配置与 128-token 模型的最佳生成结果拼接。采样序列更短，也不能证明 tokenizer 训练更便宜。

检查理解

Section titled “检查理解”
能给每个 slot 指定图像中的固定方块吗？

不能。slot 的信息通过全局学习得到；提供重建网格的是稠密输出 queries。
