AdaTok: choose a budget for an observed image

An interactive field guide

Variable-length reconstruction and deciding when to stop generating are different problems.

Before this article: TiTok · Evaluation

What was already possible

Section titled “What was already possible”

A fixed-length tokenizer spends the same number of codes on a simple image and a detailed one. A prefix-decodable tokenizer can trade length for quality. AdaTok adds a policy that chooses among discrete budgets using features of the observed input image.

Tools this method builds on

Section titled “Tools this method builds on”

Vector quantization (VQ) replaces a continuous feature by the nearest entry in a finite codebook. The stored index is discrete; the decoder receives the selected vector. A straight-through estimator supplies a training derivative across the hard choice.

A rate–distortion tradeoff balances code length against reconstruction error. A shorter token sequence is not automatically a lower bit rate: codebook count, channel width and numeric precision also matter. Count the representation payload separately from encoder and decoder computation.

What changes, and why

Section titled “What changes, and why”

Nested tail masking trains useful prefixes of a TiTok-S-style code sequence. The allowed lengths are 32, 64, 96, 128, 160, 192, 224, and 256. Each budget has a rank-16 LoRA decoder head. After tokenizer training, freeze it and train a small budget-selection MLP using relative advantages across the eight reconstruction choices.

Every shorter code is a prefix of the longer code

Section titled “Every shorter code is a prefix of the longer code”

Nested tail masking trains a tokenizer to reconstruct after truncating the end of its latent sequence. This encourages early slots to hold useful information at several budgets. The allowed lengths are 32,64,96,128,160,192,224 and 256. Each budget has a rank-16 LoRA decoder adaptation. A short prefix is therefore trained as a valid interface, not created by arbitrary post-hoc deletion.

z1:K=E(x),x^b=Dθ+Δθb(z1:b),b∈{32,64,…,256}z_{1:K}=E(x),\qquad \hat x_b=D_{\theta+\Delta\theta_b}(z_{1:b}),\qquad b\in\{32,64,\ldots,256\}z1:K​=E(x),x^b​=Dθ+Δθb​​(z1:b​),b∈{32,64,…,256}

LoRA adds a low-rank update ΔW=BA to a frozen or shared weight path according to the training stage. Rank 16 limits the update’s rank, not the number of image tokens. Decoder adaptation helps accommodate the different information available at each prefix length. Preserve which budget selects which adapter when saving a checkpoint.

Work through the mechanism

Section titled “Work through the mechanism”

The demo lets you set signal complexity and code budget. Its analytic decoder keeps enough basis coefficients to represent a chosen frequency. It shows how a quality constraint could favor different budgets. It does not implement the learned selector, and the displayed 256/budget ratio is not measured acceleration.

The policy sees encoder features of the original image. During unconditional generation, that image does not yet exist. A fixed target length that matches the average selected length does not reproduce autonomous stopping. The paper leaves visual EOS for future work.

A policy trades distortion against token use

Section titled “A policy trades distortion against token use”

After tokenizer training, freeze it and train a small budget selector on encoder features. For each image, evaluate all eight candidate budgets and obtain their reconstruction errors. The policy can learn to allocate longer codes to images where extra tokens help more. It still pays for obtaining the encoder features; reducing transmitted IDs does not necessarily reduce encoder work.

J(b;x)=D(x,x^b)+λb,Ab=rb−mean⁡b′rb′std⁡b′rb′+εJ(b;x)=D(x,\hat x_b)+\lambda b,\qquad A_b=\frac{r_b-\operatorname{mean}_{b^\prime}r_{b^\prime}}{\operatorname{std}_{b^\prime}r_{b^\prime}+\varepsilon}J(b;x)=D(x,x^b​)+λb,Ab​=stdb′​rb′​+εrb​−meanb′​rb′​​

The first expression is a simple rate–distortion interpretation. The second illustrates the group-relative normalization used in the policy approach; the paper also adapts weights. Standardization removes absolute reward scale. Two images can have the same normalized advantages but very different absolute errors, so this is not a proof of per-image optimal rate–distortion allocation.

Work through a small budget decision

Section titled “Work through a small budget decision”

Suppose a teaching example has distortions 0.020 at 32 tokens and 0.012 at 64 tokens. With λ=0.0001 per token, the costs are 0.0232 and 0.0184, so the larger budget wins. With λ=0.0003, they become 0.0296 and 0.0312, so the shorter budget wins. These are invented arithmetic inputs, not AdaTok measurements.

A policy conditioned on a known image can make this choice. A source-free image generator does not yet have that image’s encoder features. The paper leaves a visual EOS mechanism for autonomous generation stopping to future work. Its throughput comparison fixes a target length near the adaptive mean; it does not demonstrate a learned stop decision for every generated image.

Training is not sampling

Section titled “Training is not sampling”

Tokenizer training precedes the roughly 330K-parameter policy. The policy compares multiple budgets per image, balancing MSE and token count through relative normalization and dynamic weights. Relative normalization does not guarantee an exact per-image rate-distortion optimum. Encoding still creates the full candidate sequence before selection.

Evaluate the selector as well as the tokenizer

Section titled “Evaluate the selector as well as the tokenizer”

Verify that all eight prefixes decode, that truncated tokens cannot leak through attention, and that adapter selection matches the budget. Freeze the tokenizer during policy training and include all candidate reconstruction costs in the training budget. At evaluation, report the full length distribution, mean length and tail quality, not only mean token count.

The reported adaptive row uses about 118 tokens on average and has rFID 1.50; the full 256-token row has rFID 1.31. A generation gFID reported for the full setting cannot be attached to the adaptive reconstruction row. The paper did not provide a pinned official implementation in the existing reading, so code-level reproduction remains unverified.

What this does not establish

Section titled “What this does not establish”

The reported roughly 2.1× AR throughput uses a fixed 118-token target length, chosen to match the adaptive mean. It is not dynamic generation with a learned stop rule. The full 256-token MaskGIT gFID of 2.28 cannot be attached to the adaptive 118-token reconstruction row. No fixed official code revision was audited.

Check your understanding

Section titled “Check your understanding”
Why cannot the same budget policy directly choose a length before unconditional generation?

It needs features of an observed source image. Generation has no such source, so a different stopping mechanism is required.
