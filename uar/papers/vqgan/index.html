VQGAN: a tokenizer that preserves perceptual detail

An interactive field guide

Pixel accuracy alone can make reconstructions smooth. VQGAN combines a discrete bottleneck with perceptual and adversarial training, then models its codes with a Transformer.

Before this article: VQ-VAE · Attention and autoregression · Evaluation

What was already possible

Section titled “What was already possible”

VQ-VAE already learns a dictionary and a decoder. PixelCNN-style priors model the code sequence. GANs already encourage realistic image statistics, and pretrained feature networks already provide perceptual distances. VQGAN combines these tools into a compact image tokenizer plus an autoregressive Transformer prior.

Tools this method builds on

Section titled “Tools this method builds on”

Vector quantization (VQ) replaces a continuous feature by the nearest entry in a finite codebook. The stored index is discrete; the decoder receives the selected vector. A straight-through estimator supplies a training derivative across the hard choice.

Freezing parameters stops their updates. It does not necessarily stop derivatives with respect to network inputs. A frozen feature extractor used on a reconstruction may still need an active input-gradient path; an encoder used only to supply fixed targets may run without that path.

  • Details: vq

What changes, and why

Section titled “What changes, and why”

The first-stage convolutional encoder reduces image size. Nearest-code quantization retains a discrete interface. The decoder is trained with pixel and LPIPS losses, while a patch discriminator distinguishes real from reconstructed image regions. An adaptive weight can balance reconstruction and adversarial gradients at the decoder’s last layer.

One tokenizer, two uses

Section titled “One tokenizer, two uses”

First separate reconstruction from generation. Reconstruction starts with a known image. The encoder compresses that image, a quantizer replaces each feature by a codebook vector, and the decoder returns pixels. Generation starts with sampled code IDs. It uses the same decoder, but it does not encode a target image. The Transformer belongs to this second use.

For an illustrative 256 × 256 input and a factor-16 encoder, the feature grid has 16 × 16 locations. A codebook with 1,024 entries needs 10 fixed-length bits per ID: 256 IDs need 2,560 bits before entropy coding and metadata. The embedding width is not the number of bits per ID. Neither this count nor a low reconstruction loss alone establishes generation quality.

Work through the mechanism

Section titled “Work through the mechanism”

Vary the detail amplitude in the signal demo. Matching fine structure lowers paired error only when its phase and strength match the target. A plausible extra oscillation is not necessarily the original detail. The example exposes why realism and exact reconstruction require separate evidence; it does not simulate a GAN or LPIPS network.

Why a discrete choice still trains

Section titled “Why a discrete choice still trains”

At one grid location the encoder emits a vector zₑ. The nearest-neighbour search returns an integer index k. Its exact derivative with respect to zₑ is zero almost everywhere and undefined at boundaries. Backpropagating through argmin therefore cannot train an encoder by the usual path. Straight-through substitutes an identity derivative while preserving the quantized forward value. It is an estimator, not the true derivative of nearest-neighbour assignment.

zST=ze+sg⁡(ek−ze),LVQ=∥sg⁡(ze)−ek∥22+β∥ze−sg⁡(ek)∥22z_{\rm ST}=z_e+\operatorname{sg}(e_k-z_e),\qquad L_{\rm VQ}=\|\operatorname{sg}(z_e)-e_k\|_2^2+\beta\|z_e-\operatorname{sg}(e_k)\|_2^2zST​=ze​+sg(ek​−ze​),LVQ​=∥sg(ze​)−ek​∥22​+β∥ze​−sg(ek​)∥22​

sg means stop-gradient: keep the value but set its derivative to zero. The first loss moves the selected code toward the encoder output. The second commits the encoder output to the code. With scalar zₑ=0.7 and selected code eₖ=1, the forward value is 1. The two squared distances are 0.09, but they update different parameters. A larger β strengthens commitment; it does not add more codebook entries.

The displayed equation is the conventional objective. The audited VectorQuantizer2 implementation preserves an older beta placement when legacy=True. Record that switch when loading a checkpoint. Equal tensor shapes do not imply equal optimization.

LPIPS: compare features, not just pixels

Section titled “LPIPS: compare features, not just pixels”

L1 compares corresponding pixel values. Moving an edge by one pixel can make many terms large even when the object still looks similar. A feature loss first maps each image through a pretrained network, then compares the resulting activations. That changes what counts as a similar image. It does not make the comparison universally correct: features can underweight small text, exact colors, or details outside their training distribution.

LPIPS means Learned Perceptual Image Patch Similarity. Its calibration is learned from human perceptual comparisons. A pretrained backbone alone is not the whole metric. In the VQGAN implementation, a VGG16 backbone supplies five feature levels. Each spatial feature vector is normalized across channels. Squared differences are passed through learned 1 × 1 linear layers, averaged over spatial positions, and summed over levels.

The notation a denotes effective weights in the implementation. The LPIPS paper also writes a channel multiplier inside a squared norm; its squared value plays this role. Spatial averaging avoids making a level larger only because it has more positions. Unit-length normalization removes feature magnitude from this local comparison. Multiple levels combine different receptive fields.

During VQGAN training these calibrated parameters are frozen. The loss must still differentiate through the feature network to the reconstructed image. Setting requires_grad=False on parameters permits that. Wrapping the reconstructed branch in no_grad would remove the useful gradient. Input scaling also matters: this implementation applies a fixed scaling layer to inputs expected in the tokenizer image range.

PatchGAN and two different gradients

Section titled “PatchGAN and two different gradients”

A discriminator is a learned critic. PatchGAN outputs a grid of scores: each score judges an image region through its receptive field. It does not need a single label for every object, and it does not compare the target and reconstruction pixel by pixel. The generator tries to raise scores for reconstructed images; the discriminator tries to separate real and reconstructed regions. This explains why adversarial detail can look plausible without matching the original detail.

LD=12E[max⁡(0,1−D(x))]+12E[max⁡(0,1+D(sg⁡(x^)))],Ladv=−E[D(x^)]L_D=\tfrac12\mathbb E[\max(0,1-D(x))]+\tfrac12\mathbb E[\max(0,1+D(\operatorname{sg}(\hat x)))],\qquad L_{\rm adv}=-\mathbb E[D(\hat x)]LD​=21​E[max(0,1−D(x))]+21​E[max(0,1+D(sg(x^)))],Ladv​=−E[D(x^)]

The hinge margins stop rewarding a correctly classified region once it crosses the margin. The generator loss is different: it continues to seek a larger fake-image score. For the generator step, freeze critic parameters but keep its input gradient. For the discriminator step, detach the fake image. Mixing these operations can waste memory or train the wrong network.

x_hat = decoder(quantizer(encoder(x)))
# G step: frozen LPIPS and D weights; input gradients remain
loss_g = rec(x, x_hat) + weight * (-D(x_hat).mean()) + loss_vq
# D step: a separate optimizer; stop the image branch
loss_d = hinge(D(x), D(x_hat.detach()))

Balance gradient influence, not scalar loss sizes

Section titled “Balance gradient influence, not scalar loss sizes”

Two losses with similar scalar values can produce very different gradients. VQGAN measures the reconstruction and adversarial gradients at the decoder’s last layer. Their norm ratio rescales the adversarial branch. This is a local balancing rule: it does not prove that every layer receives equal updates or that the GAN game is stable.

λ=sg⁡ ⁣[clip⁡ ⁣(∥∇WLLrec∥2∥∇WLLadv∥2+ε,0,104)]λdisc\lambda=\operatorname{sg}\!\left[\operatorname{clip}\!\left(\frac{\|\nabla_{W_L}L_{\rm rec}\|_2}{\|\nabla_{W_L}L_{\rm adv}\|_2+\varepsilon},0,10^4\right)\right]\lambda_{\rm disc}λ=sg[clip(∥∇WL​​Ladv​∥2​+ε∥∇WL​​Lrec​∥2​​,0,104)]λdisc​

If the two gradient norms are 0.2 and 0.01, the unscaled ratio is about 20. Increasing the adversarial gradient norm to 0.1 reduces that ratio to about 2. Detaching the ratio avoids optimizing through the weighting rule itself. The audited code uses epsilon 1e-4, while the paper writes 1e-6. The discriminator factor also gates the GAN term until its configured start step.

Training is not sampling

Section titled “Training is not sampling”

The discriminator and generator have different updates. Stop gradients through fake images for the discriminator step; freeze discriminator parameters for the generator step while allowing gradients to its input. LPIPS features are fixed during this use. The Transformer prior is trained after the tokenizer, predicting shifted code IDs with cross-entropy.

The inspected taming implementation retains a legacy quantizer option that places β on the old term. Its adaptive-weight epsilon also differs from the paper. Read the exact version before copying a training recipe: a repository default is not automatically the paper configuration.

A reproducible boundary for this implementation

Section titled “A reproducible boundary for this implementation”

Treat the code commit, preprocessing, checkpoint, optimizer states and loss switches as one recipe. Start with the tokenizer alone. Verify an encode–lookup–decode round trip, nonzero encoder gradients through straight-through, no LPIPS parameter updates, and no decoder gradients in the discriminator step. Then verify checkpoint resume with both optimizers and the global step. Only after these checks should a reconstruction evaluation be interpreted.

The pinned imagenet_vqgan.yaml is one reference configuration: resolution 256, a 1,024 × 256 codebook, factor-16 downsampling, base learning rate 4.5e-6, batch size 12 per process, disc_start 250001 and disc_weight 0.8. The launcher multiplies base learning rate by batch size, device count and accumulation. These are not universal VQGAN settings and are not the missing VAR tokenizer recipe.

In stage two, freeze the trained tokenizer and convert images to code IDs. Train the prior with shifted IDs and cross-entropy; test the causal mask for target leakage. Report reconstruction metrics separately from generation FID, sampling temperature and truncation settings. A browser demonstration validates none of these trained-model results.

What this does not establish

Section titled “What this does not establish”

Adversarial training adds an optimizer, a schedule, and possible instability. A perceptually convincing reconstruction can change small letters or textures. The paper’s full image-generation quality includes the second-stage Transformer and its sampling settings, not just the tokenizer.

Check your understanding

Section titled “Check your understanding”
Does a Transformer generate the first-stage reconstruction?

No. The tokenizer uses convolutional encoding and decoding. The Transformer models the discrete codes in the second stage.
