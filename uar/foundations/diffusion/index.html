Diffusion and flow: learn a path from noise

An interactive field guide

A generative model can produce an image through many small corrections. The training target determines what each correction means.

Before this article: Probability and tensors · Autoencoders

What was already possible

Section titled “What was already possible”

An AE maps one input to one compact code, then decodes it. A probabilistic generator must also describe uncertainty: many images can satisfy the same class or text. Denoising models learn local predictions at different noise levels rather than mapping a single code directly to final pixels.

What changes, and why

Section titled “What changes, and why”

DDPM adds Gaussian noise through a forward process and learns reverse transitions. Flow matching instead regresses a velocity field along chosen probability paths. They are related families, but their targets and solvers are not interchangeable. Here we use a straight interpolation as a fully computable flow example.

Read from left to right. Select a module to connect its role, tensor shape, and calculation. Snippets are teaching pseudocode. Sources provide the paper method or audited implementation.

Construct a noisy pair

The target is known because training has the clean image.

xt = (1-t)*x + t*noise
target = noise - x

Learn a vector field

Condition c can be a class, text, or a reconstruction code.

prediction = model(xt, t, condition)
loss = mean((prediction-target)**2)

Integrate backwards

Use decreasing times for this convention.

state = noise
for t, t_next in schedule:
    state += (t_next-t)*model(state,t,condition)

A local training target becomes a global sampling process

Section titled “A local training target becomes a global sampling process”

Training can choose a random time independently for each example and supervise one network evaluation. Inference starts from noise and repeatedly evaluates the learned field along its own trajectory. The model is not given the clean endpoint at inference. Numerical integration error, learned-field error and missing conditioning information are separate sources of reconstruction error.

A squared velocity or noise loss does not make the final output a direct conditional-mean regression. The target depends on a noisy state and time, and sampling begins from random noise. The randomness and repeated state updates allow a conditional distribution over final outputs.

Work through the mechanism

Section titled “Work through the mechanism”

Set clean value x=2 and noise ε=−1. Our convention is t=0 for data and t=1 for noise. Then xₜ=(1−t)x+tε=2−3t and target velocity ε−x=−3. To generate, move time backwards: x at the next time equals the current x plus a negative time step multiplied by predicted velocity.

At t=0.5, xₜ=0.5. With five remaining Euler steps, Δt=−0.1, so the next value is 0.8. The demo knows the true constant velocity. A trained network sees noisy input and conditions, not the clean endpoint; its estimate can be wrong. More steps therefore have no quality benefit in this exact straight-line example.

Core derivation

Section titled “Core derivation”

Differentiate the constructed straight path with respect to t while holding the sampled endpoints fixed. This gives the supervised velocity target. A learned field averages the conditional targets compatible with its input and conditions.

Euler approximates an integral over a short interval by the current velocity times the interval. With decreasing time, Δt is negative. For the constant-velocity example, the approximation is exact; in a learned nonlinear field it generally is not.

Training is not sampling

Section titled “Training is not sampling”

Training samples x, ε and t, constructs xₜ, and regresses the known target with squared error. It need not run the complete sampling trajectory for each training example. Sampling starts from noise and repeatedly calls the learned network. Count these calls as number of function evaluations, or NFE. A stochastic diffusion sampler and a deterministic ODE solver require different update rules.

The smallest useful solver test

Section titled “The smallest useful solver test”

Choose known endpoints and an exact constant velocity. Verify that forward noising reaches both endpoints and reverse integration recovers the clean one. Then change the number of steps: the constant-velocity example should remain exact apart from floating-point error. Only afterward test a learned nonlinear field. Keep time direction, target parameterization and update sign together in every configuration.

What this does not establish

Section titled “What this does not establish”

A model may predict noise, clean data, velocity, or a score. Conversion needs the matching schedule and time convention. Copying a velocity target from one implementation and an update sign from another can reverse the process. In a reconstruction decoder, the compact image code is an extra condition; in unconditional generation there is no observed input image.

Check your understanding

Section titled “Check your understanding”
Why can training use one sampled time while generation uses many steps?

The target velocity is known for a constructed training pair at any sampled time. At generation, the unknown data endpoint must be reached by integrating the learned field.
